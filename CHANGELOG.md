# Changelog

All notable changes to this project are documented here.
Format: [Keep a Changelog](https://keepachangelog.com/en/1.1.0/). Versioning: [SemVer](https://semver.org/).

## [Unreleased]
### Fixed
- `scio build` commits the install phase's manifest and lockfile changes (`npm install --save` rewrites `package.json` and writes `package-lock.json`) on the milestone branch as `chore: install approved dependencies [scio:install:<M>:<node>]`, before the first feature's reset could delete the lockfile; a merged milestone no longer leaves a dirty tree (I-085). `load`'s sync of `progress.json` with `PRODUCT.md` is committed the same way (`[scio:sync:<M>:plan_milestone]`) instead of being reverted by that reset.
- The node scaffold no longer writes a non-registry dependency (`file:`, `github:`, a URL or a path) into `package.json` as a package of that name; the install phase writes it. Such a spec is also its own name on the approved list, so it only matches itself in `install_deps` (I-088).

## [0.6.0] - 2026-10-26
### Added
- `check_release_cadence` in `scripts/check_docs.py`: the docs check fails when two milestones that `docs/PRODUCT_MODE.md` calls done are named only under `[Unreleased]` (I-086: M8 to M10 waited two weeks behind v0.5.0); CONTRIBUTING gains the release-after-every-milestone step and a merged-on-GitHub check before any post-merge step (I-087).
- M10 live milestone on the Claude Code backend: `notes_service` (TypeScript, node:http plus zod) bootstrapped by `scio new` (the planner chose `node-ts` from the stack menu) and built through M1 (three features, one advisor escalation, `npm install` through the install phase, eslint, `tsc` typecheck and build, `npm audit` and black-box acceptance all green, merged locally), $4.61 estimated, nothing billed; the done criterion of issue #51 holds on the Fake and live. Open: the install phase leaves `package.json` and `package-lock.json` changes uncommitted (I-085).
- M10 Second stack (issue #51, ADR 0014): a `node-ts` toolchain profile (`configs/profiles/node-ts.yaml`, TAP parsers in `scio/toolchain/node_ts.py`): Node 22 runs TypeScript directly, `node --test` is the runner, `tsc`, eslint and `npm audit` the quality bar (skipped while absent), `npm install` the install phase; one data-driven `ProfileToolchain` loaded from yaml with a `StackParsers` set per stack; protocol members for the product path (`acceptance_dir`, `skeleton_command`, `command_words`, `app_target`, `syntax_check_argv`, `health_probe_argv`, `detect`); `Runtime` generalised (`env_dir`, `env_marker`, optional create step and interpreter); profile detection from marker files (`Settings.toolchain=auto` is the default, `RunContext.adopt_toolchain` on the clone, the product load and the bootstrap); a `node-ts` scaffold (TypeScript walking skeleton with `node:test` smoke and acceptance tests, eslint flat config, CI with `setup-node`); the normaliser, acceptance runner, `run_app`, tool descriptions and Claude Code allow-rules speak the profile's language; the toolbox context's toolchain reaches `edit_file` and `run_tests`, and `edit_file` runs the profile's syntax check (`module.stripTypeScriptTypes` for TypeScript, I-083); planner prompt v2 lists the available stacks; `resolve_command` finds npm's `.cmd` shims on Windows (I-081). The Fake `todo_api` spec builds its first milestone in Python and in TypeScript (`test_same_spec_builds_in_both_stacks`); CI installs Node 22 for the Node-dependent tests.
- M9 (issue #49), first slices: `delete_file` tool on every sandbox backend (`Sandbox.delete`; the coder and debugger have it; a new file rejected by the edit lint gate is now removed instead of left empty); the python profile declares a quality bar (`checks:` coverage with an 80% floor, wheel build, dependency audit) that `integrate` runs after the suite and lint, reporting a check whose tool is absent as skipped and failing the milestone on a real failure; coverage artifacts added to the profile's cache excludes; the Claude Code worker backend now refuses a non-local sandbox.
- M9 runtime (ADR 0013): a per-product environment (`.scio/sandbox/venv`, a plain venv with SCIO's own environment linked through a `.pth` file on a local sandbox, the profile's `test_tools` installed on any other, I-074) created by the install phase with the network open for that call only (`Sandbox.exec(network=True)`) and the approved dependencies from `PRODUCT.md` installed; `install_deps` worker tool gated by that list (an unapproved package is refused with the escalation hint; context-aware tools via `ToolDef.needs_context` / `ToolBox.context`); `run_app` starts `python -m <module>`, waits for a local health URL or the exit, and stops it (local sandbox only); the python profile's `runtime:` block.
- M9 live milestone on the Claude Code backend: `bookmarks_api` (http.server plus `pyyaml`) bootstrapped by `scio new` and built through M1 (four features, one advisor escalation, black-box acceptance against the started server, coverage passed, merged locally), $5.38 estimated, nothing billed; the done criterion of issue #49 holds on the Fake and live.
- M9 Docker default (ADR 0013 decision 10): `scio build` runs in Docker when a daemon answers and the `docker/sandbox.Dockerfile` image (Python plus git) is there, and in the local sandbox otherwise or on the Claude Code worker backend, with the first ledger line saying which and what a local sandbox does not enforce (`SCIO_PRODUCT_SANDBOX_BACKEND=auto|local|docker`). `DockerSandbox` is one persistent container per sandbox on an internal network (no route out), `python` rewritten to the product environment, a timeout inside the container keeping it; `exec(network=True)` attaches an egress-proxy sidecar (`scio/aci/sandbox/egress_proxy.py`, CONNECT-only, `Limits.network_allowlist`) for the duration of the call, so the install phase reaches the registry hosts and nothing else. `run_acceptance` starts an http product inside a non-local sandbox and probes it from inside. CI gains the `docker-live` job that exercises all of it on the runner's daemon.
- M9 acceptance (ADR 0013): `PRODUCT.md` gains a `## Runtime` section (`kind: cli|http`, module, start arguments with `{port}`, health path) that the product planner fills and the normaliser checks; the scaffold ships `tests/acceptance/` (black-box: a subprocess for a CLI, the health endpoint for an http product, which the scaffold now serves with `serve --port`); `integrate` starts an http product on a free port, runs the acceptance tests with `APP_URL`, stops it, and reports `[acceptance]` beside the other checks. The scripted Fake product `todo_api` (an http server with `pyyaml` on its approved list) runs through the whole milestone loop offline: install phase, two features, server started for the black-box tests, merge. The scaffold's test directories are packages, so unit and acceptance tests may share basenames (I-073).
- Claude Code backend (ADR 0012, issue #47): SCIO's model work can run through the unmodified `claude` binary on the owner's Claude subscription instead of the Messages API. `SCIO_PROVIDER_OVERRIDE=claude_code` sends every tool-less role through `ClaudeCodeProvider` (one restricted, tool-less `claude -p` per call, `--json-schema` for structured outputs); `SCIO_WORKER_BACKEND=claude_code` sends every tool-using turn through `ClaudeCodeWorker` (one `stream-json` session in the sandbox root with per-role `--allowedTools`, then a typed summary on `--resume`), with the transcript rendered in the shape `scio report` reads and the usage folded into the ledger and budget by `Harness.account`. Verify, commits and the gate are unchanged. `scio/loop/backends.make_worker` chooses the backend at every worker call site; `SCIO_CLAUDE_CODE_BIN` names the binary.
- On the `claude_code` backend every tier cap in `budgets.yaml` is scaled by `SCIO_CLAUDE_CODE_BUDGET_FACTOR` (default 4.0, the measured ratio of Claude Code's estimate to the API price, I-069); the binary's own budget stop is SCIO's graceful `budget` exit; a `claude -p` run that fails without a message is retried (I-068); over-long prose fields in a typed summary are trimmed rather than failing the turn (I-070). `scripts/nightly_live.py --provider claude_code` runs the nightly suites on the subscription, one trial at a time.
- `scio build --product DIR [--gh owner/name] [--decision "<text>"]` and `scio status --product DIR` (Product Mode M8, ADR 0011): the milestone loop. The orchestrator takes the first open feature of `PRODUCT.md`; an Opus `milestone_planner` groups up to four into a milestone with a tier each (normalised to a consecutive prefix); a GitHub milestone and one issue per feature are created idempotently by title (offline: files under `.scio/product/issues/`); each feature runs through the task graph as a subgraph on its own checkpoint thread (`build-<product>-<pk>-a<attempt>`) on branch `milestone/<n>` with the tier pinned and its own budget; the profile's full suite and lint run on the branch; an Opus `milestone_gate` verdict that any failing check overrides; one milestone PR (cost, escalations, plan versus done, `Closes #n`) stops for the human merge; `progress.json` and `NOTES.md` are updated on `main` and the loop continues. A crash between features or after the PR resumes with no duplicated issue, commit or PR; a feature that halts stops for one decision (`retry`, `skip`, stop). `merge and stop` records the merged milestone and ends the thread; build threads are named per starting milestone (`build-<product>-m<n>`) and `scio build` starts a fresh one once the previous ended. New state `ProductBuildState`, `FeatureRun`, `MilestonePlan`; `GitHubClient.ensure_milestone`, `ensure_issue`, `find_issue`, `pr_merged`; `Harness.child`; `scio report` renders a product view for `build-*` threads; the product graphs are registered diagrams in ARCHITECTURE.md.
### Changed
- After `scio new` every feature in `progress.json` is `todo`, the walking skeleton included: the scaffold proves the toolchain and P1 is verified by its own feature run (ADR 0011 decision 1, the M7 open question).
### Fixed
- The local sandbox no longer sets `RLIMIT_AS` on POSIX: it capped virtual address space, which V8 reserves by the tens of gigabytes, and Node's TypeScript stripper died with "Cannot allocate Wasm memory" on CI (I-084); the CPU-time and wall-clock limits stay, and `Limits.memory_mb` is enforced by Docker.
- On the Claude Code backend a `--json-schema` answer is a `StructuredOutput` tool call that Claude Code bounces with a schema error when it misses the schema; with `--max-turns 1` the model had no turn to retry and the first live http milestone crashed `error_max_turns` in the explorer's summary (I-077). Schema calls (worker summary, provider structured) get three turns and a capped summary is re-asked once with the required keys named.
- `scio new --thread X --decision ...` without `--dir` continued in a default directory instead of the one the thread was started in, so the first live http bootstrap landed under `.scio/products/` (I-076); the resume now reads the recorded directory from the checkpoint and reports an ignored `--dir`.
- The product environment exposed the base interpreter's packages (`--system-site-packages`), so CI's runner had no pytest inside it and every Fake product build stalled there while the dev machine passed (I-074); see Added. Windows Application Control blocks the venv's `pytest.exe` and `scio.exe` launchers on the dev machine: `python -m scio` exists now and CLAUDE.md uses the module forms (I-075).
- `scio new` ran the interviewer and the product planner twice and approved a draft the human never saw: a node re-runs from its start on resume, and both nodes made their model call and interrupted in the same node (I-065, found by the first live run after M8). The stops are now their own nodes (`answers`, `approval`) reading the draft from state; a Fake test with a planner whose draft changes every call guards it.
- Verify's "something changed since the base commit" check read `git diff --stat`, which ignores untracked files, so a feature delivered only by new files stalled as "no changes" (I-063); `diff_stat` lists untracked files and the full diff stages them with `git add -N`.
- `uv.lock` recorded the project at 0.3.0 after two releases (I-062); relocked, and `test_version.py` now checks the lock.

## [0.5.0] - 2026-10-12
### Added
- `scio new --prompt "<idea>" --dir <path> [--gh owner/name]` (Product Mode M7, ADR 0010): a product graph that interviews the user (two to four Opus questions), writes a normalised `PRODUCT.md`, stops for approval, then bootstraps a repository with the profile's scaffold (package with `--version`, smoke test, CI, README, CHANGELOG, LICENSE, `.gitignore`, `NOTES.md`, `.scio/product/progress.json`), runs lint and tests as ground truth and commits with a `[scio:bootstrap]` marker. Every human stop is an interrupt resumed with `scio new --thread ID --decision "<text>"`; bootstrap steps are idempotent effects. New roles `interviewer` and `product_planner`; new state `ProductState`.
### Changed
- Toolchain profiles (ADR 0009, Product Mode M6): every stack-specific command and parser (pytest argv and exit codes, ruff lint, syntax check, test-path rules, cache excludes, dependency files, error signatures, the prompt phrases that name tests) moved behind `scio.toolchain.Toolchain`, with the `python` profile in `configs/profiles/python.yaml` reproducing the pre-M6 behaviour byte for byte. `Settings.toolchain` selects the profile; `test_toolchain.py` guards the boundary.
- `scio run --tier` pins the route as well as the budget (I-053); without `--tier` the router decides and a default budget is resized for the tier it picks (`RunContext.apply_tier_budgets`); explicit eval budgets are untouched.
- Assumption F-8 ("targets are Python") superseded by ADR 0009; PROMPT.md's "No UI" non-goal narrowed to SCIO itself (ADR 0007).
### Fixed
- `SCIO_SANDBOX_BACKEND`, `SCIO_SANDBOX_DOCKER_IMAGE`, `SCIO_SANDBOX_E2B_TEMPLATE`, `SCIO_EFFECTS_PATH` and `SCIO_RUN_LIVE_TESTS` were declared and never read (I-054, I-059); `make_sandbox` selects the backend, `RunContext.create` honours the effects path, the live-test gate reads `Settings`.

## [0.3.0] - 2026-10-12
### Changed
- E2B is no longer a planned live tier: no account (I-029, wontfix). Local backend for own fixtures, Docker for untrusted repositories (ADR 0003).
### Added
- t008_snapshot_coupling: a formatting change that breaks a CLI snapshot test and a README example test outside the coder's filtered run; the first regression task built to make verify's full-suite step fail and the debugger run live.
- t009_verify_only_lint (T1, pinned): an undefined name in a module no test imports; the coder's `run_tests` is green and only verify's lint step fails, so the debugger must run and wire the constant rather than delete the module (hidden tests check both). First live debugger run: one turn, $0.06 of a $0.34 trial, fix plus sweep. Fake scripts gained `Step.debug_edits` for the debugger's turn.
- `tier_pin:` on an eval task runs that tier without consulting the router, which rated t008 T0 and skipped the nodes the task exists to exercise (I-050). `RunContext.tier_pin`; `route` records `classifier_model="pinned"`.
- Two realistic regression tasks: t006 (a change spanning the store module, the CLI and their tests) and t007 (a fixture whose own CI is red on `ruff` with the repo config and on `pytest`); hidden tests run the fixture's own lint rules. One live trial each passed ($0.35 and $0.40).
- Suite cost cap: `evals/runner --max-usd`; the report records spend, cap and skipped tasks.
- Nightly live suite: `scripts/nightly_live.py` (profile auth, cost cap, rows in `docs/EVAL_HISTORY.md`) registered as a Windows scheduled task on the dev machine with `--max-usd 12`; the GitHub nightly workflow gained the cap, parallel trials and auth-token secret support.
- `scio report` tool signals, counted from the worker transcripts with no model call: calls and error rate per tool, repeated identical calls within a turn, `view_file` re-reads, and whether the documenter edited docs when code changed. The documenter's transcripts are now kept as `log` artifacts like the coder's.
### Fixed
- Eval trials leaked their temp directory on Windows (636 directories): read-only git objects and an open effect-log handle, both hidden by `rmtree(ignore_errors=True)`. `remove_tree` clears the bit, `RunContext.close()` releases the handle (I-049).
- Eval fixtures are copied without `__pycache__` and tool caches, so bytecode left by running a fixture's tests in place can no longer become tracked content that shows up in the agent's commits (I-048).

## [0.2.0] - 2026-10-11
### Fixed
- Token budgets count billable-equivalent tokens (cache reads at 0.1x, writes at 1.25x) so prompt caching lowers the count it enforces (I-041).
- Prompt caching now covers the conversation: a third breakpoint on the last message block makes each worker turn re-read its transcript at cache price (I-040, `docs/IDEAS_TRIAGE.md`).
- A tool crash (e.g. `view_file` on a directory) is returned to the model as an error result instead of ending the run (I-032).
- Budget pre-check reserves half of `max_tokens` instead of all of it; explorer loops capped at 6 model calls / 8 tool calls; small task budgets raised to the tier the live router picks (I-033, I-035).
- `tests_added` wording: the tests that *prove* the features, existing or new; bug-fix tasks no longer loop on "add tests" (I-034).
- T1 verify adopts the worker's reported tests when the plan's guessed test names match nothing (I-037); worker turns capped at 12 model calls and transcripts trimmed from 30k characters (I-038); the planner no longer emits exploration steps and `normalize_steps` drops no-op steps and covers missing features (I-039).
- verify runs each reported test selector correctly: `path::name` node ids and file paths as positional pytest targets, bare words as `-k`; found by the first live Anthropic run (I-031).
- pdoc no longer warns on PEP 695 generics: `scio/prompt/repair.py` and `scio/loop/agent_loop.py` drop the `__future__` annotations import (I-008).
### Added
- `evals/runner --parallel N`: a task's trials run concurrently (independent sandboxes, checkpoints and budgets).
- Live Anthropic acceptance recorded: t001 pass^5 = 1.00 (5 trials) via an `ant auth login` profile.
- Live sandbox checks: `tests/live/test_docker_live.py` runs wherever Docker is available (CI runners included) and `tests/live/test_e2b_live.py` runs when `E2B_API_KEY` is set (I-016).

- T1 and T2 tiers in one graph builder (`scio/graph/build.py`): `scope`, parallel `explore` (LangGraph `Send`, read-only), `localize`, `plan` (plan-owned test filters), `post_plan` (issue checklist), `implement` (one step per cycle), `debug`, `advise`, `review`; generated `t1`/`t2` diagrams.
